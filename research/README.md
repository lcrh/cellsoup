# Evolution and scaling laboratory

This is ongoing work toward larger, faster, visibly interesting autonomous evolution. The interactive WebGPU model is available at `/gpu.html`; see the [current sunlight, corpse and temperature model](../docs/gpu-model.md). The older nutrient and classic-engine experiments below retain their original provenance. They do **not** establish evolved cooperation or million-cell full-lifecycle performance.

The current GPU checks run with `npm run gpu:life-check`. `node research/sunlight-field-check.mjs` checks rare bright peaks across three seeds. `npm run gpu:life-run -- --capacity=8192 --seconds=180 --sample=30` records a small autonomous trial. Add `--close-at=300 --seconds=900` for a ten-minute survival interval without immigrants after five minutes of establishment. `--minimum-birth-energy`, `--cpu-cost`, `--move-cost`, and `--turn-cost` support matched cost experiments. These use Dawn and require access to the local GPU. Historical run configurations and shader fingerprints distinguish model versions.

Tree trials are now the default (`--substrate=trees --crossover=0.25`); use `--substrate=assembly` for the comparison substrate. use `--crossover=0` to disable recombination. The [typed-tree notes](typed-trees.md) describe random program structure, host-assisted arrivals, and limitations.

## Reproduce

Run commands from the repository root. Native experiments require Clang and the platform C SDK. `CLANG` can override the compiler. On macOS the runner obtains the SDK path from `xcrun`; the compiler's stale default SDK is not used.

```sh
npm run headless -- --seed=42 --seconds=1800 --out=research/runs/baseline42
npm run headless -- --seed=42 --seconds=1800 --floor=0 --rate=8 --out=research/runs/low-arrivals42
npm run headless -- --seed=42 --seconds=3600 --selection=1 --out=research/runs/selection42
npm run research:check
npm install
npm run gpu:check
npm run gpu:bench
```

`headless` compiles `research/headless.c`, which includes the real `src/engine.c`. `CELLSOUP_RESEARCH` adds counters without changing baseline behavior. Floating-point contraction is disabled to match the WASM arithmetic. Each run saves configuration, periodic metrics, surviving and archived genomes, disassembled programs and instruction visit counts in `run.json`, plus a readable `leaders.md`. The current runner is for zero division mutation; all mutation comes from archive resampling.

Options use `--name=value`: seed (42), seconds (1800), sample interval (60), replenishment floor (2048), steady arrivals/second (8), archive share (.5), food rate (1), selection experiment (0), output directory. Selection 1 additionally requires 8 offspring, 280 absorbed food energy and 60 seconds before archival. This deliberately simple ablation is research-only, not a proposed final fitness function.

`research:check` compares two one-minute native runs with the real browser WASM: population, births, deaths, archive count, total energy and immigration accounting. The normal 65 simulator tests still apply. The uninstrumented WASM binary remains unchanged.

## What the baseline actually does

Source baseline: commit `4837421284ec55a6b645de2d145b012e39d16932`. Samples and selected programs are checked in under `results/`; full raw temporary runs are generated by the commands above.

| 30-minute run | Final cells | Largest connected body | Cells at least 60 seconds old | Imported energy | Food added |
| --- | ---: | ---: | ---: | ---: | ---: |
| Seed 42, defaults | 853 | 10 | 37 | 9,107,840 | 1,542,992 |
| Seed 97, defaults | 1,125 | 6 | 6 | 9,107,840 | 1,435,617 |
| Seed 42, no replenishment, 8 arrivals/s | 245 | 4 | 23 | 1,043,840 | 1,542,992 |

These are final snapshots, not maxima over the whole run or organism-lifetime measurements. `matureCells` measures individual age, not persistence of a multicellular lineage. `largestBody` is a connected component and can include unrelated attached cells. Actual persistent group identity, reproduction of groups, and functional dependence between members still need measurement.

Immigration supplied roughly six times as much energy as new food in the default seed-42 run. Food absorption counters include uptake of recycled carcass material, so absorption is not the same as primary food input. In the final baseline archive, 67 of 128 variants had absorbed less than 70 energy when selected; median uptake at archival was 68.28, and mean offspring count was 3.88. A low qualification threshold and nearly uniform archive sampling appear to accept short reproductive bursts too readily. The lower-arrival experiment did not by itself produce larger connected bodies.

A concrete example is baseline variant 128931 (`results/baseline42-leaders.json`): ten living members at the final sample, mutation depth seven. Its frequently visited path repeatedly attempts budding and detached division and applies maximum forward thrust. A constant conditional at instruction 13 jumps over instructions 14–26; some apparent sensing and arithmetic is dead code. Other sensory results are read but overwritten or unused. Its lifetime counters record 742.71 absorbed energy and 436.52 stolen energy, so it is not merely inert. However, ten cells sharing a program is not evidence of coordinated multicellular function. `steal 0.5 ...` also exploits the current target conversion: a positive fractional ID truncates to zero, which the internal neighbor search treats as an unrestricted query. That discrepancy between public ID semantics and internal search semantics needs resolving explicitly in the new engine.

Instruction visits mean the VM reached and paid for an instruction, not that every requested action succeeded. Archived metadata and visits are snapshots at qualification; archived `living` counts are **not** present-day population sizes. We do not infer communication, cooperation or adaptation merely from opcode presence.

### Stricter selection did not solve the ecology

Selection 1 ran for 60 simulated minutes, ending with 829 cells, a largest connected body of seven, nine cells older than a minute, and only six archive entries. The stricter gate filtered most short bursts but did not produce a clear multicellular transition. Saved programs are in `results/selection42-archive.json`.

One admitted lineage (11201) had 143 living members and 1,366 offspring at qualification. Its dominant loop is forward thrust → detached split → nearest-neighbor theft through the fractional-ID behavior → full shield → repeat. It had acquired 89,019.82 energy through theft versus 12,765.33 through absorption. The computed food gradient does not steer it: no turn instruction occurs in the active loop. Selection therefore strongly admitted a predator exploiting readily available immigrant prey, rather than directed food foraging.

A different lineage (56362) and an offspring variant (69858) repeatedly bud while stationary. After a short startup, a constant branch and backward jump trap execution in a small loop containing `gradient`, `max`, `tag` and `bud`. The gradient bearing is not used for steering or growth direction; the bud result overwrites the strength register. These can make a nutrient-fed connected colony, but the trace offers no evidence of differentiated roles or communication controlling development. That is a useful natural starting point for replay and ablation, not proof of complex multicellularity.

The next model experiment must address ecological incentives as well as sample count: stricter archival alone can select a more effective version of the same simple exploit. Both the high immigration energy input and the target-ID conversion will be explicit experimental factors.

## GPU scaling evidence and limits

The separate `gpu-kernel.mjs` experiment uses standard WebGPU and WGSL. Its kernel module has no Node imports and can also be loaded in a browser. Only the command-line harness uses Dawn's Node bindings. GPU state stays resident between ticks; each tick clears a spatial hash, inserts cells using integer atomics, then reads immutable cell state while writing a separate output buffer. Neighbor scans, repulsion, spring forces, and per-cell bytecode execution run together.

On an Apple M4 Pro with 20 GPU cores, Node 24.4.1, Dawn `webgpu` 0.6.0 and Metal:

| Cells | Median ms/tick | Speed relative to a 60 Hz simulation |
| ---: | ---: | ---: |
| 8,192 | 0.050 | 333× |
| 32,768 | 0.084 | 197× |
| 131,072 | 0.284 | 59× |
| 524,288 | 1.057 | 16× |
| 1,048,576 | 2.062 | 8× |

Measurements include command encoding, submission and waiting for GPU completion. There are 64 warm-up ticks and five batches of 256 measured ticks, followed by full readback and finite-state checks. The world expands with population, keeping density comparable across counts. Cells have fixed chains of at most two bonds, and use 4,096 shared, varied 32-instruction programs with a 24-instruction budget. This is a throughput experiment, not an evolved workload, a dense-cluster stress test or a comparison with equal-work CPU timings.

The kernel implements the arithmetic/branching/sensing/movement subset exercised by that workload. It does **not** yet implement the complete instruction set, food competition, finite-energy lifecycle, reproduction, mutation, dynamic bonds, messages, archive selection, or rendering. Those omissions can materially change performance. No end-to-end million-cell claim follows from this table.

`gpu:check` compares three ticks of 64 interacting cells against an independently written CPU implementation with budgets 0, 24 and 64. It checks positions, velocities, headings, registers, PCs, sleep and bonds. Maximum measured float error was below 0.00009. This establishes a useful starting point, not correctness of the unimplemented ecology. Atomic bin insertion changes neighbor traversal order; float sums are not promised to replay bit-for-bit.

The Dawn instance must be retained for the entire asynchronous run. An initial experiment let it become unreachable and crashed in the native event processor; the harness now keeps an explicit reference. A sandbox may prevent GPU enumeration even when Metal works outside it.

## Next experiments and completion gates

1. Extend validation and profiling of the implemented GPU lifecycle around staged intents and explicit conflict resolution. Validate food, theft, gifts, division, deaths and bond sharing with energy-accounting tests. Add controlled CPU/GPU differential cases before scaling those stages. Avoid all-pairs work and per-tick CPU readbacks.
2. Scale world area, resources and genome capacity with population rather than cramming more cells into the old arena. Measure dense colonies as well as uniform workloads, track overflow/capacity failures, and measure biological generations per wall-clock second.
3. Test selection for sustained descendants and independent establishment in fresh environments. Compare with the old archive rule, and retain random founding programs and a substantial stream of novel genomes. The main mutation channel should remain resampling unless evidence motivates a change.
4. Give connected cells a physical/ecological reason to depend on one another. A candidate is two complementary resources with costly, gradual specialization and transport across bonds. Test whether specialization and division of labor arise from the trade-off; do not simply award fitness points for having bonds.
5. Export evolved programs and developmental replays. Test lineage persistence, group reproduction, resource-driven behavior, and loss of function after disabling bonds or communication. Repeat across independent seeds and environments. Counts of bonds and births alone are insufficient.
6. Integrate the validated high-throughput engine into the browser with a fallback, direct GPU rendering, useful organism following and visible ecological events. Verify the shipped UI on actual evolved runs. Publish only after the full model is useful and the results support the claims.

Relevant primary sources for the design investigation: [WebGPU/WGSL specification](https://www.w3.org/TR/WGSL/), [Dawn Node bindings](https://github.com/dawn-gpu/node-webgpu), [task-switching costs and digital division of labor](https://pmc.ncbi.nlm.nih.gov/articles/PMC3427090/), and [evolved multicellular life histories](https://www.frontiersin.org/journals/ecology-and-evolution/articles/10.3389/fevo.2022.750837/full). These motivate experiments; they are not evidence that this simulator has already produced the same outcomes.
